# Getting help

[Home](../README.md) · [Troubleshooting](setup.md#troubleshooting) · [Validation](validation.md)

## Installation and usage

Start with [setup](setup.md), especially the standalone Node requirement and the
troubleshooting entry matching your tool error. Check [validation status](validation.md)
before assuming a scenario has been tested.

If you still need help, [open a bug report](https://github.com/GranatenUdo/local-mail-claude-extension/issues/new?template=bug_report.yml).
Use the report for reproducible failures or installation questions, and identify
which instructions you followed. Include only:

- Extension, Windows, Claude Desktop, and Node versions; architecture.
- Whether the built-in Node runtime is disabled.
- Provider name (GMX or Proton Bridge), tool name, and static error code.
- Expected behavior and synthetic steps to reproduce.

Do **not** attach raw logs, messages, attachments, account addresses, certificates,
credential-store files, or screenshots containing private information. Replace
real details with synthetic examples; a redacted mailbox dump is not a synthetic
fixture. There is no guaranteed support response time.

## Ideas and contributions

[Propose a feature](https://github.com/GranatenUdo/local-mail-claude-extension/issues/new?template=feature_request.yml)
by describing the problem and intended behavior. Read
[CONTRIBUTING](https://github.com/GranatenUdo/local-mail-claude-extension/blob/main/CONTRIBUTING.md)
before implementing a change.

## Security reports

Do not report vulnerabilities in public issues. Use
[GitHub private vulnerability reporting](https://github.com/GranatenUdo/local-mail-claude-extension/security/advisories/new)
and follow the [security reporting guidance](../SECURITY.md#reporting-a-vulnerability).
Even private reports must not include actual mailbox data or credentials.
